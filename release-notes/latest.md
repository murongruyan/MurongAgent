# MurongAgent 1.33

## 1.33 / 26072801 — 2026-07-28

本节记录 MurongAgent 1.32 之后的桌面端、Android、Windows ARM64 视觉运行时及发布流程更新。

### Added
- Desktop 与 Android 新增按执行轮次展示的文件审核卡片：汇总已编辑文件数和总 `+/-` 行数，逐文件显示增删统计，支持展开全部文件、撤销本轮改动和进入审核。
- Desktop 的文件审核可直接点击文件名，在侧边栏打开修改前后的 Diff；审核数据与执行轮次绑定，任务终止或正常总结后都可继续查看。
- Android 对齐桌面端的文件审核体验，复用会话检查点和现有 Diff 查看器，支持从聊天时间线直接检查或回退本轮文件改动。
- Desktop 设置新增“关于与更新”，明确显示当前版本、系统架构和安装包类型；应用启动后会自动检查 GitHub 最新正式 Release，并在有新版本时匹配当前平台安装包。

### Changed
- Desktop 与 Android 的执行时间线改为按实际顺序保留“模型思考 → 模型说明 → 工具活动 → 后续说明”；模型文字保持正常字号和可读状态，不再随工具卡一起折叠。
- 仅将相邻工具活动收为“已运行 N 条命令”“已编辑 N 个文件”等紧凑分组；执行中、终止后和最终总结后使用相同展示规则，并可按需展开详情。
- `list_files`、`code_search`、`run_terminal` 等内部工具名转换为人类可读说明，默认隐藏调用 ID 和内部协议参数，展开后仍保留排查所需的命令、目录、输出与结果。
- 主应用与 Desktop 默认版本升级到 `1.33`，Android `versionCode` 升级到 `26072801`。
- 终端扩展升级到 `1.11 / 26072801`；完整发布清单新增 Desktop 版本字段，Android、扩展和电脑版版本均可由客户端与 Release 审核。
- 完整发布工作流新增主 APK 与终端扩展的 `versionName` / `versionCode` 手动输入及严格校验；未填写时继续使用各项目默认版本，并将实际版本贯穿文件名、元数据和 Release。

### Fixed
- 修复 Windows ARM64 VLM 构建仍会把 MNN 的 AArch64 `.S` 汇编作为 C++ 编译、导致 `MNNTransform.vcxproj` 失败的问题；现在由 ClangCL 显式生成 ARM64 COFF 对象并链接进 MNN。
- ARM64 构建明确使用 `ARCHS=ARM64`，关闭当前 Windows 路径未验证的 ARM82、KleidiAI 与 SME2 内核，避免 Linux/ELF 专用汇编进入 Windows 构建。
- Windows 视觉运行时构建可检测 Visual Studio 2022 / 2026，并为 LiteRT 构建准备兼容的 JDK 21，降低 GitHub Actions 与本地工具链差异造成的失败。
- 修复 Android 管理端 GitHub 登录回调未被服务端允许的问题；管理端 APK 同步升级到 0.2.0，并改用与用户端一致的主题、圆角卡片、悬浮导航和深色模式。

### Verification
- Desktop 工作区审核、时间线及发布工作流契约测试通过。
- Desktop 版本比较、平台安装包选择、发布清单解析和自动更新界面契约测试通过；管理端 0.2.0 Debug APK 与终端扩展 1.11 完整工具链 APK 均已成功构建。
- Android 应用单元测试共 362 项通过，并已成功生成 `app-debug.apk`。
- GitHub Actions 将从本提交重新构建并校验 Android 主程序、终端扩展及六个平台的 Desktop 正式安装包。

## 1.32 / 26072701 — 2026-07-27

本节对比 GitHub 最新正式 Release `murong-suite-v10`（2026-07-23 08:25，北京时间；源代码提交 `5adff6a7e0963b1058542a2cff6cc958e361b1f7`）之后的工作区变化。

### Added
- 新增 Android 与 Desktop 共用的本地文本 / 视觉模型体系：模型可下载、安装、分类和选择；本地运行时会区分 CPU、GPU、文本、视觉及设备能力，不再把所有模型当成同一种推理器。
- 新增默认语音助理、悬浮会话、语音端点检测、声纹校验、快捷唤醒、通知进度与后台任务状态；语音助手可分别配置日常聊天、手机操作和代码模型。
- 新增完整的 Android 能力中心，统一展示和引导标准权限、无障碍、Shizuku、Root、通知与本地模型运行状态；补齐 GUI 自动化、前台验证、系统操作和 Phone Agent 协议实现。
- 新增端侧模型和模型目录：GLM-Edge、Qwen、Gemma、DeepSeek 等本地选项，以及官方 OpenAI 兼容、Gemini、DeepSeek、Claude 等 API 协议适配和模型思考能力配置。
- Desktop 新增本地视觉运行时、模型能力目录、工作区级会话 / 编辑器体验优化，并为 Windows 构建增加已验证的视觉运行时构建步骤。
- Desktop 模型设置新增与 Android 一致的上游模型检测和候选模型选择；OpenAI 兼容、Claude、Gemini 等连接可读取服务端模型目录，并在设置页和聊天输入栏直接切换具体模型。

### Changed
- Android 的聊天、项目、工具、设置和语音入口按电脑端工作台语义重新组织；设置页可搜索并从分类条目进入，不再依赖混杂的横滑功能区。
- 路由明确区分日常问答、实时检索、屏幕理解、手机操作、后台代码和外卖比价；普通一句“你好”不会再无条件截图或发送屏幕摘要。
- 本地模型下载不再依赖写死的官方文件大小，已安装模型会进入聊天和手机操作的完整可选列表；模型运行偏好可按设备 CPU / GPU 状态选择。
- Desktop 与 Android 的聊天输入栏现在都支持运行中引导：空输入时发送按钮变为终止按钮，输入文字或添加图片后恢复为发送按钮，可中止当前生成并基于最新聊天记录继续处理；加号和输入框在生成期间保持可用。
- Desktop 的命令执行记录改为可展开的紧凑行，展开后可查看命令、工作目录、终端、退出码、标准输出、错误输出及原始参数，不再使用普通聊天气泡或黑色截断输出块。

### Fixed
- 修复实时资讯路径：先将“搜索一下……”等语音指令清理为关键词，并按中文地区搜索；只有带来源的成功结果才交给 1.5B 本地模型总结。检索失败或总结失败会如实显示，不会再返回“我无法联网”或无证据的旧回答。
- 修复本地纯文本模型误用于视觉 / 手机操作、模型下载清单大小不匹配、安装模型未同步显示、思考内容异常字符及多家 API 的思考参数兼容性问题。
- 修复会话列表滑动后自动回退、设置项仅图标可点、预测性返回动画方向、桌面编辑区覆盖聊天区、文件标签和右键功能缺失等交互问题。
- 修复 Desktop 流式输出时强制把已上滑的消息列表拉回底部；只有用户仍停留在底部附近时才自动跟随，发送新消息或切换任务时恢复跟随。
- 修复 Windows VLM 构建脚本写死 Visual Studio 2022 的问题；现可检测 Visual Studio 2022 / 2026，并为 ARM64 使用 ClangCL 及兼容的 MNN 编译选项，避免旧构建目录和不兼容 ARM 内核导致配置失败。
- 修复完整发布工作流未同步人工维护的发布说明：构建会从触发提交读取 `release-notes/latest.md`，并在创建或更新 GitHub Release 时作为 Release 正文使用，同时仍严格校验 8 个正式安装包。

### Security
- 本地模型默认在设备内处理内容；发送截图、屏幕语义树或远程视觉请求仍需用户显式授权。Root、无障碍、Shizuku 与标准权限保持独立分级，不会因设备配对或模型选择而被静默提升。
